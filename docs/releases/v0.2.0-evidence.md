# v0.2.0 Release Evidence Dossier

**Product:** GyLiber Security Intruder  
**Release:** v0.2.0  
**Release class:** integrity and authenticity

## Acceptance contract

The release candidate is acceptable only if the exact release commit demonstrates:

- full Rust formatting/compile/Clippy/test success;
- RustSec success;
- dependency license/source policy success;
- CodeQL success;
- secure fixture → PASS;
- vulnerable fixture → FAIL;
- fixed fixture → PASS;
- valid signed target/campaign authorization succeeds;
- modified signed payload is rejected;
- wrong signer is rejected;
- expired and revoked authorization are rejected;
- role mismatch is rejected;
- revision rollback is rejected;
- envelope/payload identity mismatch is rejected;
- campaign revision mismatch is rejected;
- evidence signer is trust-preflighted before network execution;
- signed bundle verification succeeds on intact output;
- modified bundle file is rejected;
- release binary/archive/SBOM/checksum artifacts are produced;
- build-provenance and binary-SBOM attestations complete before tag/release creation.

## Pre-release implementation evidence

The complete signing/operator feature branch passed formatting, workspace compilation, strict Clippy, and the full workspace test suite before integration.

The dependency license/source policy also passed independently before it was promoted into the permanent Security workflow.

## Release identity

The authoritative release commit, workflow run IDs, asset digests, and attestation URLs are recorded after publication. Until then this document is an acceptance contract, not a statement that publication has occurred.

## Non-claims

v0.2.0 does not prove absolute security and does not authorize testing of unrelated third-party systems. It does not claim production key custody, production Command Center authorization, confidential durable evidence storage, hostname execution, or broader attack families.
