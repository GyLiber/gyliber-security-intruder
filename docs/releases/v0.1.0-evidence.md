# v0.1.0 Release Evidence Dossier

**Product:** GyLiber Security Intruder  
**Release:** v0.1.0  
**Release class:** closed-loop safety foundation

## Acceptance evidence

The release candidate is accepted only when the exact release commit preserves all of these properties:

- secure fixture → PASS;
- vulnerable fixture → FAIL;
- fixed fixture → PASS;
- arbitrary-target execution unavailable through the normal CLI;
- target host/path/network escape attempts denied by tests;
- cloud metadata endpoints denied;
- kill-switch state evaluated before request capacity is consumed;
- request total/rate/concurrency/time budgets enforced;
- evidence excludes response bodies and header values;
- evidence tampering detected by SHA-256 verification;
- target/campaign inputs reject unknown fields and schema/target mismatches;
- campaign planning is explicitly non-executing;
- run bundles are create-new and checksummed;
- normal CI passes formatting, compilation, strict Clippy, and tests;
- normal Security passes RustSec and CodeQL;
- release packaging generates binary, archive, SBOM, and SHA-256 checksums;
- provenance and SBOM attestations are produced before GitHub Release creation.

## Fixture proof

Repository fixtures are `fixtures/baseline/secure.json`, `fixtures/baseline/vulnerable.json`, and `fixtures/baseline/fixed.json`. All three are exercised through the real local TCP/HTTP execution boundary in automated tests.

## Release identity

The authoritative release commit is the commit referenced by the `v0.1.0` tag. The release binary embeds that source commit in `run.json` metadata when built by the release workflow.

## Supply-chain evidence

The release workflow uses pinned action commit SHAs; verifies the locked dependency graph; reruns all Rust quality/test gates; builds with the pinned Rust toolchain; generates a CycloneDX SBOM with pinned `cargo-cyclonedx 0.5.9`; calculates SHA-256 checksums; waits for normal CI and Security success; generates GitHub provenance and SBOM attestations; then creates the GitHub Release and tag.

## Non-claims

This release does not prove absolute security and does not authorize testing of unrelated third-party systems. Passing evidence applies only to the controls, fixture states, code revision, release artifacts, and modes actually exercised.
